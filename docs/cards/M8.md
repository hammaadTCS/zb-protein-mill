# M8: Release

## T8.1 Security checklist

**Goal:** every security and operations rule verified with evidence.

**Depends on:** T7.8.

**Build exactly:** `docs/release-checks.md` section "Security" with one row per BR-SEC-01 to BR-SEC-18 and BR-OPS-01 to BR-OPS-10: how it is enforced (file, setting or server script, from `docs/security.md` §4), how it was verified (test name, CI step or manual step), result. Fix anything missing in application code as part of this task; anything in protected files (`infra/`, `.github/`) is proposed in the pull request for the human. Rows that need a server are marked "verify on staging" for T8.3.

**Done when:** every row filled; tests pass.

---

## T8.2 Performance check

**Goal:** reports stay fast at a safe volume, and pages are light on a phone.

**Depends on:** T8.1.

**Build exactly:** `PerformanceSeeder` (local only, refuses to run when `APP_ENV=production`) creating 100,000 entries over 12 months (60% purchases, 20% sales, 15% payments, 5% expenses) through the Actions in batches; a timing script that opens every report and list page; add indexes only where a measured page is above 3 seconds. Record before/after timings in `docs/release-checks.md` section "Performance". Also record, from `npm run build` output, the JavaScript and CSS size (gzip) of the login page and of the dashboard (NFR-11).

**Done when:** every report and list loads in under 3 seconds on the measured machine (NFR-02), with the timings and sizes recorded.

## T8.3 Staging subdomain and first deploy [Human + Claude]

**Claude prepares:** `docs/developer-guide.md` for a developer who joins later: the app's folder layout as built, local setup in short (`scripts/setup-local.sh`, `.env`, `php artisan migrate --seed`, `composer run dev`), how to run every check (`scripts/check-all.sh`), how a task is merged (pull request, every check green), and links to `README.md`, `START-HERE.md`, `docs/frontend.md`, `docs/backend.md`, `docs/architecture.md` and `docs/operations/`. No server details, no secrets, no copied server steps. (`README.md` is protected and already exists.)

**You do:** build the **staging subdomain** — a second subdomain on the same Hostinger plan, with its own database and test data only (D-9) — following `docs/operations/runbook.md`, tag the first release, deploy it with `infra/hostinger/ship-release.sh`, run `zb-health-check`, check the headers, run the restore test (runbook §4), and fill the "verify on staging" rows of `docs/release-checks.md`.

**Done when:** staging works from the documents alone; release checks updated.

## T8.5 Trial month alongside the Urdu register [Human]

Real data never goes on staging (spec §18), so first build **production** as in T8.6 (setup, deploy, Owner) and run the trial there. The accountant enters one real month in the system while still keeping the register. Every week, compare cash, each bank and every party balance with the register. Each difference gets a written explanation in `docs/feedback/T8.5.md` by **voucher number, date and kind of difference only**: no party names, mobiles, bank details or amounts, because that file is in git (`docs/data-handling.md` rule 9). The names and figures stay in the company's own comparison sheet. System bugs become fix tasks for Claude with a failing test first, written with **invented** numbers that reproduce the problem, never the real entry.

**Done when:** the month closes in the system with zero unexplained differences.

## T8.6 Production and go-live [Human]

Production is built before the trial month (T8.5) with `docs/operations/runbook.md` (its own database, storage bucket and monitors, separate from staging): deploy the release approved on staging with `infra/hostinger/ship-release.sh` and create the Owner with `zb:create-owner`. After the trial: deploy any fixes through staging, prove the daily and monthly backups restore (runbook §4), do the rebuild drill (runbook §9) if not done on staging, then tick every box in spec §19.2 in `docs/release-checks.md` section "Go-live", with the date and who checked it.

**Done when:** every box is ticked.

## T8.7 Handover to the company [Human]

Complete `docs/operations/handover.md`: every account in the company's name with two-factor login, key copies with two holders, documents handed over, a person other than you restores a backup on staging using the runbook alone, alerts reach the Owner. The Owner signs.

**Done when:** the handover sheet is signed and stored with the release checks.
