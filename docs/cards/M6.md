# M6: Checks and reports

Every report: money from journal lines only, kg from purchases and sales only (spec §12.1); excludes cancelled entries and payments awaiting approval; balances in words; print-friendly.

## T6.1 Daily cash check

**Goal:** catch a cash difference on the same day.

**Client requirement:** D-25.

**Depends on:** T5.6.

**Build exactly:**
- Migration `create_cash_counts_table` per spec §9.5 including `business_closed` boolean default false; `counted_amount` nullable (null only when `business_closed`).
- Action `CreateCashCount(User, MoneyAccount cash, string $date, ?string $counted, ?string $note)`: system amount = ledger balance of that account with `posting_date <= date` (BR-CHK-02); difference = counted − system (BR-CHK-03); stored, **never posted**. Audit `cash_count_entered`.
- Action `DismissCashCount(User owner, MoneyAccount, string $date)`: stores a row with `business_closed = true`, counted null (BR-CHK-04).
- Page 28 `/cash-counts` (mobile-first): date, cash account, system amount (read-only, refreshed on date change), counted amount, live difference, note; history list below (date, counted, system, difference, user). Several counts per day allowed; the latest counts.
- Alert provider `MissingCashCount`: yesterday has no count and no dismissal for any active cash account; owner sees "Mark business closed".

**Rules:** BR-CHK-01 to BR-CHK-04.

**Tests (write first):**
- `BR-CHK-02 system amount after AT-1 day 1 is 18900.00` (cash, 2026-01-05).
- `BR-CHK-03 difference is stored and no journal is created`.
- `BR-CHK-04 dismissal clears the alert`.

**Done when:** tests pass.

## T6.3 Ageing service

**Goal:** overdue buyers, payment speed and advance age, computed one way.

**Client requirement:** D-32; spec §12.6.

**Depends on:** T6.2.

**Build exactly:**
- `App\Domain\Reports\Ageing` implementing spec §12.6 oldest-first matching per party:
  - increases for a buyer: opening "they owe", sales (fixed rate), payments paid to him; reductions: receipts, adjustments, advance opening;
  - increases for a supplier: opening "we owe", purchases (fixed), unpaid expenses to him; reductions: payments to him, adjustments, advance opening (and the mirror for advances);
  - `overdueFor(Party buyer, string $asOf): string` — unmatched part of sales older than `payment_terms_days` (0.00 when the buyer has no terms);
  - `averageDaysToPay(Party buyer, string $from, string $to): ?string` — weighted by sale amount over sales fully matched in the period, 2 decimals;
  - `advanceAgeDays(Party, string $asOf): ?int` — when the balance is an advance, age of the oldest unmatched payment (supplier) or receipt (buyer).
- Alert providers `OverdueBuyers`, `AgedAdvances` (advance age > `advance_age_days`).

**Rules:** spec §12.6; BR-CHK-06.

**Tests (write first, dataset T-12):**
- Buyer "ABC Feeds", payment terms 15 days. Sales 2026-01-01 10000.00 and 2026-01-10 20000.00; receipt 2026-01-20 15000.00. As of 2026-02-05: overdue = `15000.00`; average days to pay (2026-01-01 to 2026-02-05) = `19.00`.

- Buyer with no terms → overdue `0.00`.

## T6.8 Rate, weight difference and adjustments reports

**Client requirement:** D-11, D-12, D-13; R-10, R-11, R-12.

**Depends on:** T6.7.

- Page 39 `/reports/adjustments`: per party and reason: total, count, % of that party's sales or purchases in the range.
- Party profile tabs "Rate history" and "Weight differences".

## T6.10 Statement and entry slip PDFs

**Goal:** share a khata statement or a slip with a party.

**Client requirement:** D-35; spec §13.

**Depends on:** T6.9.

**Build exactly:**
- `composer require barryvdh/laravel-dompdf`.
- `App\Support\Format` (PHP): lakh/international grouping and date formats by string manipulation, matching `format.ts` (no `number_format`, conventions §3).
- Blade views `pdf/statement.blade.php` and `pdf/slip.blade.php` exactly per spec §13.1 and §13.2; logo `brand/zb-logo-96.png` copied to `resources/images/` at max 48 px tall, on white. Party names: the English `name` only, never `name_ur` (spec §13). Font: IBM Plex Sans if dompdf can embed it from a TTF copy in `resources/fonts/` (with its OFL licence file); otherwise dompdf's built-in DejaVu Sans. Say which in the pull request.
- dompdf options: remote file access off (`isRemoteEnabled = false`), PHP in templates off.
- Routes `GET /parties/{id}/statement.pdf?from=&to=` and `GET /purchases/{id}/slip.pdf`, `GET /sales/{id}/slip.pdf` (view permissions).
- "Share PDF" button: uses the Web Share API with the file when available, otherwise downloads.
- Not shown: cancelled entries, awaiting payments, internal notes (statement); our weight (slip).
