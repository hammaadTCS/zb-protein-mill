# M0: Setup

Facts these cards rely on were checked on 11 October 2026 and are listed in `docs/stack-baseline.md`. If anything you see differs (a command fails, a file is not where the card says, a version is different), **stop and report the difference**. Do not adapt silently.

## T0.1 Laravel app, React starter kit, Pest, PostgreSQL, CI

**Goal:** a running Laravel 13 app from the official React starter kit, with only the login features the spec allows, Pest 4, PostgreSQL, self-hosted font, and CI green.

**Client requirement:** D-38, D-44; ADR-0001, ADR-0009, ADR-0010.

**Depends on:** nothing.

**Build exactly** (run each command; stop and report at the first one that fails):

1. Check the tools and write the results into the pull request: `php -v` (must be 8.3 or newer; note the exact version), `composer -V`, `node -v` (22 or newer), `npm -v`, and that `psql -h 127.0.0.1 -U zb_test -d zb_mill_test -c 'select 1'` works (password `local_test_only`). If Composer cannot download packages, stop and say so.
2. Create the app in a **temporary folder outside the repository**, with the feature installer held back:
   ```bash
   export COMPOSER_NO_INTERACTION=1
   TMP="$(mktemp -d)"
   LARAVEL_INSTALLER_DEFER_HOOKS=1 composer create-project laravel/react-starter-kit "$TMP/app" --stability=dev --prefer-dist
   ```
   **In a cloud session** (`CLAUDE_CODE_REMOTE=true`) the GitHub proxy refuses Composer's GitHub zip downloads (`docs/stack-baseline.md`, "Cloud sessions"). From the repository root, run this block instead of the one above. The first lines only work out the package versions and build their zips from git into Composer's cache; the last line is the same command as above:
   ```bash
   export COMPOSER_NO_INTERACTION=1 COMPOSER_ALLOW_SUPERUSER=1
   REPO="$PWD"
   TMP="$(mktemp -d)"
   LARAVEL_INSTALLER_DEFER_HOOKS=1 composer create-project laravel/react-starter-kit "$TMP/probe" --stability=dev --prefer-source --no-install --no-scripts
   (cd "$TMP/probe" && composer update --no-install --no-scripts)
   bash "$REPO/scripts/cloud-composer-cache.sh" "$TMP/probe" && rm -rf "$TMP/probe"
   LARAVEL_INSTALLER_DEFER_HOOKS=1 composer create-project laravel/react-starter-kit "$TMP/app" --stability=dev --prefer-dist
   ```
   The starter kit itself then comes from git: Composer prints "Failed to download laravel/react-starter-kit from dist" and continues "from source". That is expected (git also brings the kit's `README.md` and one `.github/` file that the zip leaves out; step 7 copies neither). Every other package must load from the cache; if Composer still reports a failed download, stop and report it.
   Write the line Composer prints for `laravel/react-starter-kit` (version and commit) into `docs/installed-versions.md`.
3. Keep only two-factor login and password confirmation (removes registration, e-mail verification, passkeys; BR-USR-06):
   ```bash
   cd "$TMP/app"
   LARAVEL_INSTALLER_NO_NODE=1 php artisan install:features --no-interaction --answers='{"auth_features":["2fa","password-confirmation"]}'
   ```
   Confirm afterwards that `chisel.php`, `chisel-paths.php` and `app/Console/Commands/InstallFeaturesCommand.php` are gone and `composer.json` no longer mentions `install:features`.
4. Lock the PHP platform and add Pest 4 (Pest 5 needs PHP 8.4):
   ```bash
   composer config platform.php <the exact version from step 1, for example 8.3.6>
   composer require --dev "pestphp/pest:^4.7" "pestphp/pest-plugin-laravel:^4.1" --with-all-dependencies
   ```
   **In a cloud session**, run these three lines instead of the `composer require` line (same packages; their zips are built from git before installing):
   ```bash
   composer require --dev "pestphp/pest:^4.7" "pestphp/pest-plugin-laravel:^4.1" --with-all-dependencies --no-install
   bash "$REPO/scripts/cloud-composer-cache.sh" .
   composer install
   ```
   Create `tests/Pest.php` with exactly:
   ```php
   <?php

   pest()->extend(Tests\TestCase::class)
       ->use(Illuminate\Foundation\Testing\RefreshDatabase::class)
       ->in('Feature');
   ```
   Do **not** run `pest --init` (it would add example tests that clash with the kit's). Keep the kit's PHPUnit-style tests as they are; Pest runs them.
5. Self-hosted IBM Plex Sans instead of the font downloaded from `fonts.bunny.net` (ADR-0010):
   ```bash
   npm install
   npm install @fontsource/ibm-plex-sans
   ```
   In `vite.config.ts`: `import { fontsource } from 'laravel-vite-plugin/fonts';` and replace `bunny('Instrument Sans', { weights: [400, 500, 600] })` with `fontsource('IBM Plex Sans', { weights: [400, 500, 600] })`. In `resources/css/app.css` replace `'Instrument Sans'` with `'IBM Plex Sans'` in the font stack. Then `npm run check:fix` and `npm run build`.
6. Settings files:
   - `.env.example`: `APP_NAME="ZB Poultry Protein Mill"`, `DB_CONNECTION=pgsql`, `DB_HOST=127.0.0.1`, `DB_PORT=5432`, `DB_DATABASE=zb_mill_dev` (the database you click around in; tests use `zb_mill_test` through `phpunit.xml`), `DB_USERNAME=zb_test`, `DB_PASSWORD=local_test_only` (uncommented), `QUEUE_CONNECTION=sync`, and a new line `CSP_ENABLED=false`. Leave every other line as the kit has it. `APP_KEY` stays empty.
   - `phpunit.xml`: `DB_CONNECTION` → `pgsql`, `DB_DATABASE` → `zb_mill_test`. Remove every SQLite and `:memory:` setting.
   - Delete `database/database.sqlite` if it exists.
7. Move everything into the repository root **without overwriting or deleting any existing file**. Do **not** copy the kit's `.github/` folder (the repository has its own CI). Do not install Laravel Boost (it writes its own `CLAUDE.md`).
   The repository's `.gitattributes` already contains the kit's lines plus line-ending rules; keep it (do not take the kit's copy).
   The kit's `.gitignore` ignores `/.claude` and `/CLAUDE.md`, which this project commits: delete those two lines and add `.claude/settings.local.json` instead. Keep every other line (the Wayfinder folders `resources/js/actions`, `resources/js/routes`, `resources/js/wayfinder` stay ignored; they are generated).
8. In the repository: `composer install`, `npm ci`, `cp .env.example .env`, `php artisan key:generate`, `php artisan migrate`, then every command in "Done when".
9. Create `docs/installed-versions.md` with a table: package and exact version from `composer.lock` / `package-lock.json` for `laravel/framework`, `inertiajs/inertia-laravel`, `laravel/fortify`, `laravel/wayfinder`, `pestphp/pest`, `larastan/larastan`, `react`, `@inertiajs/react`, `vite-plus`, `laravel-vite-plugin`, `typescript`, `@fontsource/ibm-plex-sans`; the kit line from step 2; the PHP and Node versions from step 1. Compare with `docs/stack-baseline.md` and list every difference in the pull request.

**Rules:** BR-USR-06 (part: no registration, no e-mail verification).

**Tests:** the kit's own tests must pass on PostgreSQL (tests for removed features are deleted by the installer itself).

**Not in this task:** removing password reset and account deletion (T0.2), any package not named above, any model, any page.

**Done when:** `composer install`, `npm ci`, `npm run build`, `php artisan migrate`, `php artisan test`, `vendor/bin/pint --test`, `vendor/bin/phpstan analyse`, `npm run check`, `npm run types:check` all pass locally and in CI (both PHP jobs); `bash scripts/secret-scan.sh` passes; `docs/installed-versions.md` exists.

## T0.2 Project files check, brand icons, remove kit features the spec forbids

**Goal:** the repo matches the project rules before any feature work.

**Client requirement:** D-38; BR-USR-03, BR-USR-06; spec §15.7.

**Depends on:** T0.1.

**Build exactly:**
- Confirm these exist and report any missing: `docs/spec.md`, `docs/requirements.md`, `docs/tasks.md`, `docs/conventions.md`, `docs/glossary.md`, `docs/brand.md`, `docs/cards/`, `docs/acceptance/`, `docs/architecture.md`, `docs/security.md`, `infra/`, `scripts/guard.sh`, `scripts/check-protected.sh`, `scripts/secret-scan.sh`, `.claude/settings.json`, `.claude/hooks/protect_files.py`. Do not edit them.
- Icons: copy `brand/zb-monogram.svg` to `public/favicon.svg`, `brand/apple-touch-icon-180.png` to `public/apple-touch-icon.png`, `brand/favicon-32.png` to `public/favicon-32.png`. Remove `public/favicon.ico` and point the `<link rel="icon">` tags in `resources/views/app.blade.php` at `favicon.svg` and `favicon-32.png`.
- Remove from the kit (routes, controllers, pages, links, tests that cover only these features):
  - forgot password and password reset: remove `Features::resetPasswords()` from `config/fortify.php`, the reset and forgot-password pages, the "Forgot password?" link, `app/Actions/Fortify/ResetUserPassword.php` and its registration in `FortifyServiceProvider` (BR-USR-06);
  - "Delete account": the `profile.destroy` route, its controller method, the delete-account component and its tests (BR-USR-03, BR-USR-06);
  - the public welcome page: `GET /` redirects to the dashboard (which sends guests to login), and `resources/js/pages/welcome.tsx` is removed.
- Keep: login, logout, profile name/e-mail edit, change own password, appearance (dark mode), two-factor login, password confirmation.
- Login limit: the kit allows 5 attempts per minute per e-mail + IP (BR-SEC-03); keep it and test it.
- `.env.example`: `SESSION_LIFETIME=60` (BR-SEC-04).

**Rules:** BR-USR-03, BR-USR-06, BR-SEC-03, BR-SEC-04.

**Tests (write first):**
- `BR-USR-06 registration route does not exist`: `GET /register` returns 404.
- `BR-USR-06 password reset routes do not exist`: `GET /forgot-password` and `GET /reset-password/x` return 404.
- `BR-USR-03 there is no delete account route`: `DELETE /settings/profile` returns 404 or 405.
- `BR-SEC-03 login is throttled after 5 failures`.
- `the home page sends guests to login`.

Removing the kit's own tests for removed features is allowed **in this task only**; list each removed test file in the pull request.

**Not in this task:** user management page (T5.2), roles (T1.3), brand colours (T2.1), security headers (T1.12).

**Done when:** all tests pass; the removed features are unreachable; favicon shows the ZB monogram.
