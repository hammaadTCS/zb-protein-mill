# M5: Controls and settings

## T5.1 Company settings page

**Goal:** the owner fills every limit and format without a developer.

**Client requirement:** spec §4 OPEN items; BR-GEN-07.

**Depends on:** T4.8.

**Build exactly:**
- Page 42 `/settings` (`settings.manage`): every key in spec §9.6 except `opening_balances_completed`, grouped:
  - **Company:** `company_name`, `system_start_date` (read-only once any journal exists).
  - **Limits:** `payment_approval_limit`, `new_party_first_payment_limit`, `expense_party_required_limit`.
  - **Formats:** `kg_decimals`, `rate_decimals`, `amount_rounding`, `number_format`, `date_format`.
  - **Weight:** `plant_has_scale`, `slip_no_required`, `slip_photo_required`.
  - **Alerts:** `unusual_rate_percent`, `unusual_rate_lookback`, `rate_pending_age_days`, `advance_age_days`, `insights_period_months`.
  - **Security:** `owner_two_factor_required` (O-31). Turning it on while the current Owner has no two-step login shows a confirmation that they will be sent to set it up.
- A "Setup checklist" box at the top listing missing required settings (from `Settings::missingRequired()`), opening balances status and "at least one cash account".
- Each field shows the OPEN item ID it answers (for example "O-01") in small grey text, so the owner knows which client answer it needs.
- Saving uses `Settings::set()` (audited). `kg_decimals`, `rate_decimals` and `amount_rounding` become read-only once any purchase or sale exists (changing them would change how saved figures display and round).

**Rules:** BR-GEN-07; spec §9.6.

**Tests (write first):** `accountant gets 403`; `system start date is locked after the first journal`; `rounding settings locked after the first purchase`; `every change is audited`.

**Done when:** tests pass.

## T5.2 Users page and account safety commands

**Goal:** the owner adds users, sets roles and temporary passwords, and disables users; the server administrator can create the first owner and recover a locked-out owner.

**Client requirement:** C (two roles); BR-USR-02 to BR-USR-09; BR-SEC-02, BR-SEC-13; O-13.

**Depends on:** T5.1.

**Build exactly:**
- Page 43 `/settings/users` (`users.manage`): list (name, e-mail, role, status, last login from audit, two-step login on/off), add user (name, e-mail, role, temporary password typed by the Owner), change role, reset password (Owner types a new temporary password), disable/enable.
- Passwords are validated with `Password::defaults()` (the kit's rule: in production 12+ characters, mixed case, number, symbol, breach check; BR-SEC-02). Do not add a second rule.
- Actions `CreateUser`, `UpdateUserRole`, `ResetUserPassword`, `DisableUser`, `EnableUser`; audits `user_created` and `user_changed`.
  - `CreateUser` and `ResetUserPassword` set `must_change_password = true` (BR-USR-08).
  - `DisableUser`, `UpdateUserRole` and `ResetUserPassword` call `Sessions::endFor($user)` (BR-SEC-13) and audit `sessions_ended`.
- BR-USR-04: refuse disabling or demoting the last active owner (glossary "Last owner").
- No delete (BR-USR-03).
- Artisan commands (server only, no routes), each audited as `server_command` with `user_id` null and the target user in `new_values`:
  - `zb:create-owner`: asks for name, e-mail and password (hidden input, confirmation, `Password::defaults()`); refuses when any user has the Owner role; creates the Owner in the seeded company with `must_change_password = false` (BR-USR-07). When no company exists it stops with "System data is missing. Deploy a release first (zb-deploy-release runs SystemDataSeeder)." and creates nothing.
  - `zb:reset-password {email}`: generates a 16-character temporary password, prints it once, sets `must_change_password = true`, ends the user's sessions (BR-USR-09).
  - `zb:reset-two-factor {email}`: clears the user's two-factor secret, recovery codes and confirmation, ends their sessions (BR-USR-09).

**Rules:** BR-USR-02 to BR-USR-09, BR-SEC-02, BR-SEC-13.

**Tests (write first):**
- `BR-USR-04 last owner cannot be disabled or demoted`; `BR-USR-03 no delete route`.
- `BR-SEC-02 in production a password without a symbol is refused` (set `app()['env'] = 'production'` inside the test; `Password::defaults()` is evaluated when called).
- `disabled user's login is refused` (reuses T1.1 behaviour).
- `T-17 BR-SEC-13 disabling a user deletes their sessions`; `changing a role deletes their sessions`; `resetting a password deletes their sessions and sets must_change_password`.
- `BR-USR-07 zb:create-owner creates the first owner`; `refuses when an owner exists`; `refuses when system data is missing`; `is audited as server_command`.
- `BR-USR-09 zb:reset-password prints a temporary password once and forces a change`; `zb:reset-two-factor clears two-factor`; `an unknown e-mail fails with a message`.

**Not in this task:** permission editing per role (roles are fixed in version 1), e-mail of any kind.

**Done when:** tests pass.

## T5.6 Dashboard

**Goal:** one screen that shows today, balances and everything needing attention.

**Client requirement:** spec §11.3.

**Depends on:** T5.5.

**Build exactly:**
- Page 2 `/dashboard`:
  - **Today:** kg bought per item and kg sold per product (active entries, `entry_date = today`), money received, money paid (posted payments with posting date today), expenses total today.
  - **Balances:** each active money account.
  - **Alerts:** every registered `AlertProvider` the user can see, with count and link. Providers added here: `RatePendingAged` (count of pending entries past `rate_pending_age_days`; red), `PaymentsAwaitingApproval` (owner), `BuyersOverCreditLimit`, `NegativeCashBalance`, `TrialBalanceError` (owner; `TrialBalance::asOf(today)->balanced` false). Providers for overdue buyers, aged advances and missing cash count are added in T6.1 and T6.3.
  - **Quick buttons:** New purchase, New sale, New payment, Quick expense (permission-based).
- Mobile layout: Today and Alerts first, balances after.

**Rules:** spec §11.3; BR-LED-10 (alert part).

**Tests:** `today figures after AT-1 day 1 with today frozen at 2026-01-05` (waste 1800.000 kg bought; protein 500.000 kg sold; received 41000.00; paid 70000.00 (40000 + 10000 + 20000); expenses 11100.00); `accountant sees no owner-only alerts`.

**Done when:** tests pass; screenshot at 375 px.
