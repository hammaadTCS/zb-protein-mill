# Developer guide

For a developer who joins later. It describes the app **as built** and how to work on it. It has no server details and no secrets: those live in `docs/operations/` and `docs/secrets.md`.

Read these first: `README.md`, `START-HERE.md`, `docs/README.md` (map of every document), then `docs/architecture.md`, `docs/backend.md` and `docs/frontend.md`. The rules for what to build are in `docs/spec.md` and `docs/cards/`; how code is written is in `docs/conventions.md`.

## 1. Folder layout

| Folder | What is in it |
| --- | --- |
| `app/Domain/<Module>/` | All business logic, one folder per module: `Purchases`, `Sales`, `Payments`, `Expenses`, `Adjustments`, `Partners`, `Transfers`, `OpeningBalances`, `Parties`, `Items`, `MoneyAccounts`, `Ledger`, `Periods` (month-end), `Checks` (cash counts), `Reports`, `Insights`, `Alerts`, `Audit`, `Attachments`, `Backups`, `Numbering`, `Settings`, `Users`, `Companies`. Inside a module: `Actions/` (one class per user action, with `handle()`), `Models/`, `Enums/`, `Policies/`, and helper classes |
| `app/Domain/Ledger/` | `PostingService` (the only code that writes journal rows), `PostingRules` (one builder per posting rule PR-01 to PR-27, plus the party merge), `LedgerBalance`, `IntegrityCheck` (`zb:verify`) |
| `app/Domain/Reports/` | Report queries (`Queries/`), PDF documents (`Documents/`), the ageing method (`Ageing.php`) |
| `app/Http/Controllers/` | Thin controllers: check the permission, validate, call one Action or query, return an Inertia page or a redirect. Report pages are in `Reports/` |
| `app/Http/Middleware/` | Content Security Policy, forced password change, forced Owner two-factor, disabled users |
| `app/Support/` | Money maths on strings (`Decimal`), number and date formats (`NumberFormat`, `Dates`, `Format`), today in Asia/Karachi (`Today`), idempotency, warnings, company scoping (`Tenancy/`) |
| `app/Console/Commands/` | Server commands: `zb:create-owner`, `zb:reset-password`, `zb:reset-two-factor`, `zb:verify`; local only: `zb:time-pages` |
| `database/migrations/` | One migration per table, with the database protections (triggers that block updates and deletes, check constraints) |
| `database/seeders/` | `SystemDataSeeder` (runs on every server: company, settings keys, roles, system accounts, items); local only: `DatabaseSeeder`, `TestSettingsSeeder`, `TestExpenseCategoriesSeeder`, `DemoSeeder`, `PerformanceSeeder` |
| `resources/js/pages/` | One React page per screen, in folders that match the URLs |
| `resources/js/components/app/` | The app's own shared pieces (party picker, money and kg text, entry forms, khata table, dialogs). `components/ui/` holds shadcn/ui parts |
| `resources/js/lib/` | `money.ts` and `format.ts` (string-based number handling, no floats), `navigation.ts` (the menu as data) |
| `resources/js/routes/`, `actions/`, `wayfinder/` | Generated by Wayfinder from the Laravel routes. Not committed; made by `npm run build` |
| `resources/views/pdf/` | Blade views for the statement and slip PDFs |
| `routes/web.php` | Every application route, each with `->can('permission')` |
| `routes/console.php` | The schedule (`zb:verify` daily at 20:30 UTC) |
| `tests/Feature/` | Feature tests per module; `tests/Acceptance/` runs the acceptance files; `tests/Arch/` holds the architecture rules; `tests/Support/AcceptanceRunner.php` runs `docs/acceptance/*.json` through the real Actions |
| `docs/acceptance/` | The numbers the system must produce (AT-1 to AT-6). Tests read them; never copy numbers into code |
| `infra/` | Server scripts and their tests. Never run against a server from a development machine |
| `scripts/` | Local setup, the full check (`check-all.sh`), the guard and the secret scan |

## 2. Local setup in short

1. Once per computer: `bash scripts/setup-local.sh` (PHP, Composer, Node, PostgreSQL, the two local databases `zb_mill_test` and `zb_mill_dev`, `.env` from `.env.example`).
2. `composer install` and `npm install` if the setup script did not.
3. `php artisan key:generate` (only when `.env` has no key yet).
4. `php artisan migrate --seed` — creates the tables, the system data, the test settings and the local owner `test@example.com` (password `password`, local only).
5. Optional demo data: `php artisan db:seed --class=DemoSeeder`.
6. `composer run dev` — starts the app at http://127.0.0.1:8000 with Vite.

## 3. Running every check

`bash scripts/check-all.sh` runs everything CI runs, in the same order: tests (`php artisan test`, PostgreSQL only), Pint, Larastan level 7, vite-plus lint and format (`npm run check`), TypeScript (`npm run types:check`), front-end tests (`npm test`), the project guard, the secret scan and the dependency audits. It must print **ALL CHECKS PASSED** before a pull request.

Useful single commands:
- `php artisan test --filter="BR-PUR-03"` — one rule's tests.
- `npm run build` — builds the assets and the Wayfinder route files (needed before page tests and `types:check`).
- `php artisan zb:verify` — the integrity check on your local data.
- `php artisan zb:time-pages` — page timings on a database filled by `PerformanceSeeder` (see `docs/release-checks.md`, "Performance").

## 4. How a change is made and merged

1. Every change belongs to a task card in `docs/cards/` (or a change request, spec §20.3). Work on a task branch, never on `main`.
2. Write the test first for anything that posts money; name tests with the rule ID.
3. Run `bash scripts/check-all.sh` until it passes.
4. Open a pull request with `.github/pull_request_template.md` filled in. The developer merges it on GitHub only when every check is green.
5. Protected files (listed in `CLAUDE.md`) change only through a pull request with `[spec-change]` in its title.

## 5. Things that are easy to get wrong

- **Money, kg and rates are strings**, never floats: `App\Support\Decimal` in PHP, `lib/money.ts` in React.
- **Only `PostingService` writes journal rows**; every posting is one of the builders in `PostingRules`. Edits and cancels are reversals.
- **Nothing is deleted**: database triggers block it.
- **Every query is scoped to the company**; models with `BelongsToCompany` do it for you.
- **Closed months are locked**: `Periods::assertValidEntryDate` and `PostingService` refuse them.
- **Words on screens come from `docs/glossary.md`**; party balances are words ("We owe", "Advance"), never a minus sign.
- **Each new route** goes into the route table of `tests/Feature/Permissions/RoutePermissionTest.php` (T-09).
- **Answers to the user are not errors**: an exception that only carries a message for the screen (like `WarningRequired` or `ConcurrentEdit`) goes into `dontReport` in `bootstrap/app.php`, so its text (which can hold a party name) never reaches the log (BR-SEC-17).
- **Inertia DevTools is off.** To use the browser extension on your laptop, set `INERTIA_DEVTOOLS_ENABLED=true` in `.env`. It works only with `APP_ENV=local`, and it saves every page's data under `storage/inertia-devtools/`: delete that folder when you are done.
- **No links or files from other sites** on any screen (BR-SEC-14); `tests/Feature/Security/ProtectedAppTest.php` fails if one appears.
